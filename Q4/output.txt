=== PART A: prediction (before running) ===
PREDICTED: (b) join and (c) f-string+join are fastest and grow in step with the number of lines, O(n).
           (a) += looks O(n^2) because a string is immutable: every += should copy the whole text built so far.
           BUT CPython sometimes resizes the string in place, so (a) may only be a constant factor slower.
           With a second reference to the string (build_plus_aliased) the in-place trick is impossible -> clear O(n^2).

=== PART F: alternative - StringIO and writing line by line to a file ===
method                  time (s)   peak extra memory (MB)
join (list + join)        0.0101                    15.92
io.StringIO               0.0071                     6.86
+= loop (a)               0.0096                     3.05
write to file             0.0410                     0.03
(memory measured with tracemalloc; the shared input list of 200,000 lines is created before measuring and not counted)
join: O(n) time, memory = the list of 200,000 small strings + the final text (the largest of the four here). StringIO: O(n) time, one growing buffer.
file: O(n) time, O(1) memory (only the current line), the statement never exists as one big string.
+= loop: up to O(n^2) characters copied in the worst case (shown in PART D); CPython's in-place resize hides this only for a single-reference local string.
