=== PART B: Inquiry - immutability and slicing ===
s[0] = 'T' -> TypeError: 'str' object does not support item assignment
s.upper() returns a NEW string: 'TN09AB1234' | s is still 'tn09ab1234' | same object? False
only s = s.upper() makes the name s point to the new string: 'TN09AB1234'
Why strings are immutable: they are hashable dictionary keys, safe to share between variables, and their hash never changes.
9-character number 'KA01M0007':  s[-4:] = '0007'   s[4:-4] = 'M'   (series letters: 1)
10-character number 'TN09AB1234': s[-4:] = '1234'   s[4:-4] = 'AB'   (series letters: 2)
s[-4:] is always the 4-digit number; s[4:-4] is whatever lies between the district and the number = the series (1 or 2 letters).

=== PART D: alternative concept - regular expression vs slicing ===
50,000 random plates, slicing result == regex result for every plate: True | valid plates in sample: 32970
method                   time for 50,000 plates (s)  per plate (us)
slicing + isalpha                            0.0095           0.189
re.fullmatch (cached pattern)                       0.0179           0.358
Time: both examine each character at most once -> O(L) for a number of length L (L is at most 10 here).
Readability: the regex states the pattern in one line, [A-Z]{2}[0-9]{2}[A-Z]{1,2}[0-9]{4}; the slicing version needs the length check
and three slices. Ease of change: allowing 3 series letters is a one-character regex edit ({1,3}) but needs a new length test and slice rule in the slicing version.
Note: the regex pattern does not accept the non-ASCII digit trap above because [0-9] means only ASCII digits.
